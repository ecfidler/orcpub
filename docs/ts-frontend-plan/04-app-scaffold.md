# Phase 3: Scaffold the TypeScript app

The goal is a running `web-ts/` app with routing, auth, the API client,
and the engine package connected, proven by a working flow from login to
character list against the real backend.

## Stack choices

| Concern | Choice | Rationale |
|---------|--------|-----------|
| Build | Vite | Fast, with zero-config TypeScript and React |
| UI | React 18 and TypeScript | The ClojureScript app already renders through React (Reagent), so the rendering model is the same |
| Routing | react-router | The route table mirrors the `route_map.cljc` page routes |
| Server state | TanStack Query | Caching and retries for the API endpoints. Replaces the ad-hoc ajax in `events.cljs` |
| Client state | Zustand or Redux Toolkit | One store: the current entity, the auth token, and UI state |
| Wire | transit-js codec (doc 02) | |
| Rules | `@dmv/pubdoor` (doc 03) | An async-loaded chunk |
| Tests | vitest and Playwright | Golden files and a few end-to-end flows |

Redux Toolkit is the closest match to re-frame if you ever need to
cross-reference the old code: `events.cljs` corresponds to actions and
reducers, `subs.cljs` to selectors, and `views.cljs` to components.
Zustand needs less boilerplate. Either works.

## Project layout

```
web-ts/
  src/
    api/          # transit codec + typed endpoint functions (doc 02)
    engine/       # thin wrapper around @dmv/pubdoor: async load, debounced build
    state/        # store: auth slice, character slice, homebrew slice
    routes/       # route table; one dir per page (doc 05)
    components/   # shared UI (option cards, ability blocks, modals)
    styles/       # see "Styling" below
  fixtures/       # Phase 0 captures
  e2e/
```

## Dev-server proxy and CORS

Run the Clojure backend unchanged on port 8890 and put Vite's dev proxy in
front of it, forwarding `/dnd`, `/login`, `/register`, `/user`,
`/character.pdf`, and `/check-*` to localhost:8890. The dev backend
already allows all origins (`system.clj`), but the proxy keeps everything
same-origin, so cookies (for password reset) and CSP behave as in
production.

For production, the simplest deployment is unchanged: serve the built
`web-ts/dist/` from any static host, or from the backend's public
resources directory, with the API on the same origin.

## Auth slice

- On `POST /login`, store the token in memory and localStorage. Decode
  nothing. Treat the JWT as opaque.
- Attach `Authorization: Token <jwt>` in the API client.
- A global 401 handler clears the token and redirects to login.
- The registration flow: live validation with `check-username` and
  `check-email` as in the current form, then `POST /register`, then the
  "verification email sent" screen.

## Character state model

This is the central design decision. The recommended shape:

```
store.character = {
  entity: StrictEntity,          // single source of truth, opaque
  built: BuiltCharacter | null,  // derived, debounced
  selections: AvailableSelection[], // derived, debounced
  dirty: boolean,
}
```

Every UI mutation goes through `engine.selectOption` or `setValue` and
produces a new `entity`. A debounced effect, about 150 ms trailing, like
the ClojureScript app's debounced `entity/build` in `subs.cljs`, recomputes
`built` and `selections`. Saving posts `entity` verbatim to
`POST /dnd/5e/characters`. Loading sets it verbatim from
`GET /dnd/5e/characters/:id`. TypeScript code never interprets the strict
entity. Only the engine reads it.

The current app autosaves drafts to localStorage (`autosave_fx.cljs`).
Replicate that with a persisted-store middleware.

## Styling

The current CSS is generated by Garden (`src/clj/orcpub/styles/core.clj`)
plus static files in `resources/public/css`. Do not port it. Pick Tailwind
or CSS modules and restyle from the rendered reference app. A fresh
stylesheet is the one part of a rewrite that costs nothing extra. Copy
static assets (the logo, icons, and fonts in `resources/`) as needed, and
note the font and asset licenses.

## Milestone for this phase: M1, the read-only client

Ship, in order:

1. The scaffold, the proxy, and the Transit codec round-tripping the
   fixtures.
2. The login page, which stores the token and shows `GET /user`.
3. The character list page from `GET /dnd/5e/character-summaries`.
4. The read-only character sheet: `GET /dnd/5e/characters/:id`, then
   `engine.buildCharacter`, then a rendered sheet that matches the
   reference app for the golden characters.

Step 4 exercises every risky integration (Transit, auth, the engine
boundary, and bundle loading) end to end before any builder work starts.

## Exit criteria

- [ ] Login, logout, and registration work against the real backend
- [ ] The character list renders for the test user
- [ ] The read-only sheet renders the golden characters with matching computed values
- [ ] CI runs the typecheck, vitest (the codec and engine golden tests), and one Playwright smoke test
